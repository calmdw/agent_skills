# Portability Checklist

Use this before promoting project-born content into this library.

- [ ] no task-specific reward details are embedded as reusable rules
- [ ] no task-specific success thresholds are embedded as reusable rules
- [ ] no simulator-specific implementation notes are presented as generic method
- [ ] no controller-specific assumptions are presented as generic method
- [ ] no cluster-specific commands, paths, usernames, or partitions are written
      as universal guidance
- [ ] stack-bound details are clearly labeled instead of hidden in core rules
- [ ] `When To Use` is explicit
- [ ] `When Not To Use` is explicit
- [ ] intentionally excluded project details are listed
- [ ] templates exist when they materially improve reuse
- [ ] the content can be understood without first reading one project's docs
